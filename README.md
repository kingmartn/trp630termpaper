# Household trip generation analysis

The notebooks contain executable code; methods and interpretation are documented in the separate Markdown result files.

Run the analysis from this project folder with the `geo_env` Python environment:

```bash
source /home/mst_lab/geo_env/bin/activate
```

1. Run `Household_EDA_updated.ipynb` from top to bottom. It checks the source workbook, uses the saved household split, and writes 23 EDA tables and 16 figures under `final_outputs/EDA/`. Modeling summaries use eligible training households; pre-exclusion vehicle reviews use training-assigned households. Held-out records go to `intermediaries/EDA_heldout_test.xlsx` and are absent from EDA summaries.
2. Run `MLR_regression.ipynb` from top to bottom. It fits the prespecified simple regression with household persons, vehicles, full-time workers, and students. It then searches alternative linear-regression specifications using training households and evaluates the selected model on the reserved test households. The separate `final_outputs/MLR_regression/feature_rationale.md` explains the transportation reason and interpretation limit for every candidate effect.
3. Run `python cross_classification.py`. The top-level script fits trip-rate cells on training households, evaluates on the same test households, and writes the side-by-side comparison files.

The common split is generated by [`split_policy.py`](split_policy.py) on every run: sort the source household IDs, shuffle them with NumPy PCG64 seed `42`, and assign the first rounded 30% to test before applying the common exclusions. `intermediaries/EDA_training.xlsx` stores the resulting assignment for audit; it is never used to choose the split. Run the analyses in the order above so both model workbooks use the regenerated IDs. Use reserved-test scores as final evaluation and training-only validation for further model changes.

The written report, literature review, research questions, and presentation slides are separate assignment deliverables.
